# manYOUscript mobile (Capacitor)

Wraps the same React app (`@manyouscript/app-shell`) used by desktop and
web, packaged natively via [Capacitor](https://capacitorjs.com/).

## What's here

- `capacitor.config.ts`, `vite.config.ts`, `src/main.tsx` — the Capacitor
  web build, wired to `CapacitorVaultAdapter` from `@manyouscript/fs-adapters`.
- `android/` — a real, Gradle-based Android Studio project generated by
  `npx cap add android`.
- `ios/` — a real Xcode project generated by `npx cap add ios`. This
  exists in the repo but was **generated on Linux**, where iOS builds
  aren't possible — it needs to be opened and built on a Mac.

## Building

```bash
pnpm --filter @manyouscript/mobile build   # builds the web bundle to dist/
pnpm --filter @manyouscript/mobile cap:sync # copies dist/ into android/ and ios/
```

Then, on the appropriate machine:

- **Android**: open `apps/mobile/android` in Android Studio (or run
  `./gradlew assembleDebug` with the Android SDK installed and
  `ANDROID_HOME` set), then run on a device/emulator.
- **iOS**: open `apps/mobile/ios/App/App.xcworkspace` in Xcode on a Mac,
  then run on a device/simulator.

## Why there's no "pick a folder" flow on mobile

Desktop (Tauri) and the web app (Chromium's File System Access API) both
let the user pick any folder on disk as their vault. Mobile has no
equivalent without adding a native Storage Access Framework / document-
picker plugin (not included yet — a real gap, not an oversight). Instead,
`CapacitorVaultAdapter` works inside one fixed, app-owned folder
(`Documents/manyouscript-vault`), created automatically the first time
the app opens.

## Getting your vault onto — and staying in sync across — your phone/tablet

Because there's no in-app sync (matching how Obsidian Mobile relies on
the OS's own file sync rather than implementing one itself), cross-device
continuity means putting `manyouscript-vault` under a folder your OS
already keeps in sync:

- **iOS**: `Info.plist` already sets `LSSupportsOpeningDocumentsInPlace`
  and `UIFileSharingEnabled`, so the app's `Documents/` folder shows up
  in the Files app once built. From there, move your existing iCloud
  Drive vault's files into that folder, or use an iCloud Drive folder as
  your working vault and copy/symlink it in.
- **Android**: there's no built-in equivalent yet; the practical options
  today are a file-manager app that can copy files into the app's
  Documents directory, or a sync client (Dropbox, Google Drive, Syncthing)
  configured to mirror into that same path. Real SAF-backed folder access
  is future work, tracked as the same "no arbitrary-folder access on
  mobile" gap noted above.

## What's verified vs. not (as of Phase 6)

This was built and verified in a Linux sandbox with no Android SDK, no
Xcode, and no device or emulator available, so the verification bar is
necessarily lower here than for the other platforms:

- ✅ `CapacitorVaultAdapter` (adapter + directory-walking logic) has real
  unit tests against a mocked `@capacitor/filesystem`.
- ✅ The Vite web build (the same bundle Capacitor wraps) typechecks and
  builds cleanly, and its responsive/touch layout was verified with
  Playwright at a phone viewport size against `apps/web`.
- ✅ `npx cap add android` produces a real, complete Gradle project
  structure (verified: `./gradlew tasks` runs and gets as far as
  resolving the Android Gradle Plugin — it fails there only because this
  sandbox has no Android SDK and its network policy blocks
  `dl.google.com`, both environment limits, not code problems).
- ✅ `npx cap add ios` produces a real Xcode project structure, though it
  cannot be opened, built, or run outside of macOS.
- ❌ Nothing here has run on an actual Android/iOS device or emulator.
  Before shipping, someone needs to open both native projects on their
  respective platforms and do a real click-through.
